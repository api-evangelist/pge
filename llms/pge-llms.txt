# Pacific Gas and Electric — Share My Data (Green Button Connect My Data)

> Generated by API Evangelist on 2026-07-27 from all/pge/apis.yml and the artifacts in this repo. PG&E serves no /llms.txt of its own (HTTP 404 on www.pge.com, api.pge.com and sharemydata.pge.com, probed 2026-07-27), so this file is GENERATED, not harvested.

Pacific Gas and Electric Company is the investor-owned electric and natural gas utility for northern and central California. Its API surface is Share My Data, a production NAESB REQ.21 ESPI 1.1 Green Button Connect My Data implementation running on a MuleSoft gateway at https://api.pge.com. The whole developer contract — endpoint reference, OAuth guide, XSD schemas, SDKs, rate limits, release notes — is published anonymously on pge.com without a login. The DATA is not open: access requires a US EIN, CPUC eligibility, a CA-issued X.509 client certificate, tariff acceptance, mandatory registration testing, PG&E approval, and then an individual customer's OAuth authorization. PG&E publishes no first-party OpenAPI; its machine-readable contract is XSD and its API reference is PDF. PG&E publishes no open market or grid API.

## APIs

- [PG&E Share My Data (Green Button Connect My Data) ESPI API](https://www.pge.com/en/save-energy-and-money/energy-saving-programs/smartmeter/third-party-companies.html): ESPI 1.1 REST API returning Green Button Atom/XML — interval usage, usage summaries, reading types, billing, account, tariff/rate plan and demand response enrollment. Base URL https://api.pge.com/GreenButtonConnect/espi/1_1/resource. Mutual TLS 1.2 plus bearer token on every call.
- [PG&E Share My Data OAuth 2.0 Authorization API](https://www.pge.com/en/save-energy-and-money/energy-saving-programs/smartmeter/third-party-companies.html): OAuth 2.0 authorization server implementing the NAESB ESPI authorization profile. Base URL https://api.pge.com/datacustodian/oauth/v2. Separate test server at https://api.pge.com/datacustodian/test/oauth/v2. Not OpenID Connect.

## Notes for agents

- There is no self-serve access. Do not attempt to obtain credentials programmatically; registration is a screened, approval-gated business process.
- Every production call requires a client X.509 certificate over mutual TLS in addition to the bearer token. An anonymous call returns HTTP 400 "Invalid Certificate".
- Dates in query parameters must be Zulu (UTC). Other formats are rejected.
- Responses are Atom/XML, not JSON. There is no JSON representation of ESPI resources.
- PG&E publishes no MCP server, no GraphQL, no Postman collection and no first-party OpenAPI.
